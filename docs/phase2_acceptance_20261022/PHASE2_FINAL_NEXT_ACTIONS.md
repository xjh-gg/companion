## P1

### P1-1 目标端并发压力验证

- 问题：主机测试为单线程，目标端未做高频 MCP 查询与状态变化交错压力。
- 证据：`state_machine.c` 已加短临界区，但未在目标端压测。
- 下一步：用外部 MCP 客户端或本地测试脚本连续调用 `get_status`，同时触发拿起/按键，观察 10 分钟。
- 完成标准：无 panic、无看门狗、返回字段不出现跨状态组合。
- 需要用户：提供 MCP 客户端或授权测试脚本；代码无需再改。

### P1-2 实际扬声器听音

- 问题：60 分钟提醒的播放请求与 codec 打开已证实，但未确认扬声器实际出声。
- 证据：`boot_log_60min_20261022.log` 有播放请求、codec open、output enable。
- 下一步：保持待机等到 60 分钟，或使用安全的短提示音测试入口；人工听音。
- 完成标准：听到犯困提示音。
- 需要用户：人耳确认。

### P1-3 MCP 外部调用

- 问题：`get_status` / `get_recent_events` 只验证到注册，未验证真实 `tools/call`。
- 证据：启动日志有 Add tool；无请求/响应日志。
- 下一步：通过小智服务端 MCP 客户端调用两个工具，核对 state、传感器、事件历史。
- 完成标准：返回真实 JSON，空历史/上限/非法参数行为符合设计。
- 需要用户：外部客户端或服务端授权。

## P2

### P2-1 真实断网/恢复

- 问题：仅有静态重连路径，未制造断网。
- 证据：`wifi_station.cc:244-259`、`mqtt_protocol.cc:17-30,78-90`。
- 下一步：在可控网络条件下断开热点 30 秒再恢复，观察本地传感器/状态机连续性与重连日志。
- 完成标准：无重复任务、无崩溃、恢复后 MQTT 重连。
- 需要用户：可控断网操作。

### P2-2 报警状态可达性

- 问题：`EVT_ALARM` 无生产者，STATE_ALARM 不可达。
- 证据：全树无 `event_queue_send(EVT_ALARM)`。
- 下一步：产品决策——实现触发源或删除状态。
- 完成标准：状态机无死状态。
- 需要用户：产品决策。

### P2-3 MQTT 陪伴事件上报

- 问题：MQTT 仅承载小智协议，不上报陪伴事件。
- 证据：`mqtt_protocol.cc` 无 companion 事件发布。
- 下一步：确认是否需要云端遥测；若需要，设计独立 topic 与离线缓存。
- 完成标准：至少一个事件可被服务端观察，或明确不上报。
- 需要用户：产品决策。
