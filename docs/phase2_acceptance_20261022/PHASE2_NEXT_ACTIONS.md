## P1

### P1-1 实现陪伴 LED 物理反馈

- 问题：`companion_led_request` 只打印日志，不驱动 GPIO1；拿起/摇晃/靠近没有可见反馈。
- 证据：`main/companion/companion_led.cc:15-34`；启动日志“LED 适配占位初始化”。
- 下一步：确认 GPIO1 灯珠类型与 XiaoZhi `SingleLed` 的仲裁方式；在不破坏小智原有状态灯的前提下，把陪伴模式映射到可见灯效，或明确产品上放弃独立 LED。
- 完成标准：物理拿起/摇晃时观察到与 HAPPY 对应的灯效；小智语音状态灯不被破坏。
- 需要改代码：是。

### P1-2 接入按键事件

- 问题：`EVT_KEY_PRESSED` 无生产者，F4 按键交互未实现；SLEEPY 只能靠语音/动作退出。
- 证据：全树未发现 `event_queue_send(EVT_KEY_PRESSED)`；`state_machine.c:123,166,181` 仅有分支。
- 下一步：通过 XL9555 KEY0–KEY3 或现有 Button 组件产生按键事件；定义短按/长按语义；避免与 BOOT 键的配网/对话功能冲突。
- 完成标准：按键可产生事件、进入历史、按设计迁移状态；实机日志可复现。
- 需要改代码：是。

### P1-3 犯困提醒失败重试/降级

- 问题：进入 SLEEPY 时若设备非 idle 或音频忙，提醒请求返回 false 后不再重试；提醒可能永久丢失。
- 证据：`companion_audio.cc:69-89`；`state_machine.c:85-87` 只打印警告。
- 下一步：在 SLEEPY 状态增加有限次重试或“音频空闲后补播”机制；明确最大重试次数与放弃条件，避免打扰。
- 完成标准：在音频忙场景下，提醒能在合理时间内补播或明确记录放弃；不重复刷屏。
- 需要改代码：是。

### P1-4 当前固件扬声器实际发声验收

- 问题：只有 codec 初始化证据，没有当前固件播放请求和人工听音证据。
- 证据：启动日志 `Audio codec started`；无播放日志；`PlaySound` 无返回值。
- 下一步：在安全、可恢复的测试入口下播放一次 OGG_POPUP（例如现有提醒入口），人工确认声音；不要改动正式 60 分钟参数。
- 完成标准：听到预期提示音，且不影响小智语音对话。
- 需要改代码：否（需要测试入口/人工听音）。

## P2

### P2-1 状态机与 MCP 并发读同步

- 问题：状态机字段由 `companion_main_task` 写，MCP 回调在主事件循环读，无锁/原子。
- 证据：`companion_service.cc:117-166`；`mcp_server.cc:557`。
- 下一步：为状态机增加一致性快照接口（短临界区或原子快照），MCP 只读快照；避免在回调内长时间持锁。
- 完成标准：并发读不再直接触碰写侧字段；主机测试或压力测试验证字段一致性。
- 需要改代码：是。

### P2-2 犯困定时事件进入历史

- 问题：`EVT_TIMER_SLEEPY` 直送状态机，未写事件历史，MCP 最近事件看不到。
- 证据：`state_machine.c:209`；`companion_event_log_record` 只在主任务队列消费处调用。
- 下一步：在进入 SLEEPY 时同步记录一次事件（带时间/ALS/PS/valid），保持 `EVT_TIMER_SLEEPY` 单次。
- 完成标准：`get_recent_events` 能看到犯困触发；序号/排序正常。
- 需要改代码：是。

### P2-3 报警状态可达性或删除

- 问题：`EVT_ALARM` 无生产者，STATE_ALARM/急促闪为死代码。
- 证据：全树未发现 `event_queue_send(EVT_ALARM)`；状态机有分支。
- 下一步：产品决策——要么定义报警来源（例如长按/紧急按键）并实现，要么删除 STATE_ALARM 与相关 LED 模式，避免文档误导。
- 完成标准：状态机不再包含不可达状态，或报警有可复现触发路径。
- 需要改代码：是（取决于产品决策）。

### P2-4 MQTT 陪伴事件上报

- 问题：MQTT 只承载小智协议，陪伴事件不上报；M4“数据上报”未落地。
- 证据：`mqtt_protocol.cc` 无 companion 事件发布；`get_status.mqtt_state` 固定 `unsupported`。
- 下一步：明确是否需要云端事件上报；若需要，设计独立 topic/消息格式、鉴权、离线缓存与限流，不复用小智私有协议。
- 完成标准：至少一个陪伴事件可被服务端观察到，或产品明确不上报。
- 需要改代码：是（若产品要求上报）。

### P2-5 传感器初始化错误传播

- 问题：AP3216C/QMA 初始化写寄存器返回值未检查，失败可能延后暴露。
- 证据：`ap3216c.c:66-80`、`qma6100p.c:80-101`。
- 下一步：对关键写操作检查返回值并返回明确错误；保留现有初始化序列与参数。
- 完成标准：I2C 失败时初始化返回错误并记录可定位日志；正常路径不变。
- 需要改代码：是。

### P3-4 事件队列丢弃计数原子性
