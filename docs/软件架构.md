# 软件架构设计

## 分层架构

```
┌─────────────────────────────────┐
│        应用层 (main)            │
│  app_main → 初始化 + 事件循环   │
├─────────────────────────────────┤
│        BSP 驱动层               │
│  每个模块独立 .c/.h，对外暴露 API │
│  IIC / LED / KEY / XL9555      │
│  QMA6100P / AP3216C / BUZZER   │
├─────────────────────────────────┤
│     ESP-IDF / FreeRTOS          │
│  GPIO / I2C / Timer / Log       │
├─────────────────────────────────┤
│     硬件 (DNESP32-S3)           │
└─────────────────────────────────┘
```

## FreeRTOS 任务划分

| 任务名 | 优先级 | 周期 | 职责 |
|---|---|---|---|
| sensor_task | 5 | 50ms | 读 QMA6100P + AP3216C，判断拿起/摇晃/靠近事件 |
| key_task | 4 | 20ms | 扫描 4 个按键，去抖 |
| led_task | 3 | 10ms | 根据当前心情状态控制红灯闪烁 |
| buzzer_task | 3 | 事件触发 | 播放提示音 |
| main_task | 1 | 1s | 心跳日志、定时提醒检查 |
| network_task | 2 | 事件触发 | WiFi 连接 + MQTT 周期上报 |

> 已拆多任务：app_main 仅做初始化 + 创建任务；状态机迁移、语音会话逻辑（预留）运行在 main_task 的周期 tick 中。

## 数据流

```
传感器 → 事件检测 → 状态机更新心情 → LED/蜂鸣器回应
              ↓
         事件日志（串口打印）
```

## 模块依赖关系

```
main.c
  ├── iic_init()          → IIC 模块（总线初始化）
  ├── xl9555_init()       → XL9555 模块（依赖 IIC）
  ├── led_init()          → LED 模块（直接 GPIO）
  ├── qma6100p_init()     → QMA6100P 模块（依赖 IIC）
  ├── ap3216c_init()      → AP3216C 模块（依赖 IIC）
  ├── buzzer_init()      → BUZZER 模块（依赖 XL9555）
  ├── motion_detect       → 拿起/摇晃检测（取 QMA6100P 数据）
  ├── event_queue         → 统一事件队列（sensor/key 生产者 → 状态机）
  ├── state_machine       → 5 状态机（迁移表 + 联动 LED/蜂鸣器）
  ├── config              → 配置管理（读 AT24C02，联动犯困定时）
  ├── event_log           → 环形事件日志（标 AT24C02）
  └── network_task        → wifi_manager + mqtt_manager（上报状态）
```

## 设计原则
- **BSP 模块化**：每个传感器一个文件夹，.c 实现 + .h 接口
- **高内聚低耦合**：main.c 只调用各模块的 init 和读函数，不关心内部寄存器
- **错误容忍**：I2C 读取失败不卡死，打印日志后继续
- **事件驱动**：传感器只在状态变化时产生事件，不轮询
